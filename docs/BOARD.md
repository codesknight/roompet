# 开发板（需求 / 待办 / 已完成）

> 这份文件是**仓库里的开发板**：每一项需求一行，写明状态、属于哪一轮、以及"凭什么说它做完了"。
> 它和 GitHub 上的 issue / milestone 是同一批内容的两个视角——issue 用来讨论与跟踪，
> 这里用来一眼看清整个项目的全貌（以及**哪些只是写了计划、哪些真的验证过**）。
>
> 状态图例：✅ 已完成且验证 ｜ 🔶 已完成但验证有限 ｜ 🚧 进行中 ｜ 📋 待办 ｜ ⏸ 明确推迟 ｜ ❌ 不做

> 需求逐条的详细实现与证据见 [REQUIREMENTS.md](REQUIREMENTS.md)；
> 踩过的坑与交接信息见 [DEVLOG.md](DEVLOG.md)。

## 一、交互与界面

| 编号 | 需求 | 状态 | 轮次 | 实现与证据 |
|---|---|---|---|---|
| I1 | 点击宠物能做不同的动作 | ✅ | 9 | `PetInteraction`：点/戳宠物 → 按**性格与状态**挑一个反应（躲开、蹭手、翻肚皮、甩尾巴、装睡、炸毛…）。手机上是**点击**（触摸射线命中宠物），桌面是鼠标点击 |
| I2 | 点击宠物发出声音、说话 | ✅ | 9 | 反应会同时：①播放该物种+性格的**程序化叫声**；②以第一人称写一行反应进对话（不花 token，本地文案） |
| I3 | 不同宠物不同性格不同音色 | ✅ | 9 | `PetVoice`：基频/滑音/颤音/音节数由**物种**（狐/猫/兔/熊）+ **性格四维**共同决定，纯波形合成，可单测 |
| I4 | 语音输入（STT） | 🔶 | 12-14 | `DshMobile.MobileStt`（安卓 `SpeechRecognizer`）：麦克风按钮在折叠聊天栏里，按一下**展开聊天并开始听**，识别到的字填进输入框（不直接发送，听错了还能改）。四处平台坑都按文档处理了：Android 11 的 `queries` 加 `android.speech.RecognitionService`、麦克风**运行时权限**、`RecognitionListener` 十个回调一个都不能少、以及**国产 ROM 需要 `EXTRA_CALLING_PACKAGE`**（少它会被回 `ERROR_CLIENT`）。没权限时按下就申请，**拿到权限自动开始听**（不再要求"再点一次"）。**识别准确率仍只能真机验证** |
| I5 | 语音输出（TTS） | 🔶 | 10-14 | 第 10 轮做了 `DshMobile.MobileTts`（安卓 `TextToSpeech`），第 11 轮修掉**真机上听不到**的两个原因（`queries` 包可见性、初始化失败被永久记住），第 12 轮修掉 `setPitch/(F)V` 的 `NoSuchMethodError`（那两个方法**返回 int**，要用 `Call<int>`）。第 14 轮修掉最后一道：**朗读默认是关的**，于是"宠物还是不会说话"——现在默认打开，「▶ 测试朗读」也会顺手打开。**发音质量仍只能在真机上听** |
| I6 | 语音系统可开可关 | ✅ | 9-14 | 两个独立开关：`PetVoice.Enabled`（叫声，默认开）与 `MobileTts.Enabled`（朗读，**第 14 轮起默认开**，和叫声一致——一个要翻设置才开口的宠物不是会说话的宠物）。语音输入另有 `MobileStt.Enabled`（默认开，不开就不显示麦克风） |
| I7 | 每只宠物一张状态卡 | ✅ | 11 | `PetGameManager.Cards()` 给房间里每只宠物一份卡片数据（名字/物种/性格/需求/控制器），`PetHud.DrawPetCards` 用**宠物名字做页签**渲染；点房间里的宠物 = 选中它的卡片（`PetClickTarget` → `SelectPetObject`）。同伴的需求以前**根本不衰减**（只有主宠被 tick），现在一起 tick，并按所在地应用同样的修正 |
| I8 | 状态卡可隐藏 / 可打开 | ✅ | 11 | 卡片可折叠：折叠后只剩页签 + 一行摘要 + `展开/地图/设置`；展开时是完整卡片。点已选中的页签切换折叠。折不下时会自动退回短卡（`ComputeCardLayout` 的三条规则，单测逐个视口验证） |
| I9 | 删掉与背包重复的「换一只」卡片 | ✅ | 11 | 那张卡被整段删除（连同 `DrawSpeciesSwitcher`），并在原处留了注释说明为什么：它和「宠物」面板的背包页重复，而且那个按钮会**静默换掉你正在照顾的那只**（连记忆一起）。房间里有谁由背包决定，卡片只负责"读" |
| I10 | 保留「视角」卡片 | ✅ | 11 | `ViewCardHeight` 固定高度，位置由 `HudLayout.Switcher` 决定；新卡片与它、与聊天面板**互不重叠**（单测用真实矩形做 `Rect.Overlaps` 检查） |

## 二、玩法

| 编号 | 需求 | 状态 | 轮次 | 实现与证据 |
|---|---|---|---|---|
| G1 | 开门解锁新场景 | ✅ | 10 | 门 → **地图**面板：小屋 / 花园 / 夜晚露台，价格 0 / 500 / 900 宠物币；点「解锁并搬入」一次完成购买与搬家 |
| G2 | 不同场景激活宠物不同状态 | ✅ | 10 | `RoomThemeInfo` 带需求修正（花园开心掉得慢、脏得快；露台更容易累），房间重建时同时改环境光 |
| G3 | 地图功能 | ✅ | 10 | `PetWorldMap` 存档解锁与当前所在地；场景是**重建**而不是三个 `.unity` |
| G4 | 拼图小游戏 | ✅ | 11 | `PetPuzzle`（纯逻辑 8×8 状态机 + 可逆性单测）+ `PuzzleArt`（按当前房间与宠物程序化画一张 96×96 的图）+ `PetHud.DrawPuzzle`（9 格滑动拼图，点空格旁的块滑动，带步数/计时/参考步数/看原图）。**不占新场景**：它需要的棋盘和图片，房间本来就能画。拼好给 8–40 宠物币，进对话与记事本。入口在「地图」面板的"在屋里玩"一节 |
| G5 | 小鸟飞行小游戏 | ✅ | 11 | 新程序集 `DshMiniGames` + 新场景 `Assets/MiniGames/Scenes/FlyBird.unity`（由菜单从代码生成）。`FlyBirdRules` 是纯逻辑（点击抬升、限速、难的曲线有上限、间隙永远不会关死、帧率无关、长帧钳位），`FlyBirdGame` 是玩法，`FlyBirdHud` 是界面。每过一根管子 1 币（每 5 根多 1 币），撞到即结算入账。实测：50 秒游戏时间内过 84 根、赚 100 币，钱进的是同一份 `PetWallet` |
| G6 | 跳一跳（原横版平台玩法，按要求改版） | ✅ | 11-12 | 新场景 `Assets/MiniGames/Scenes/JumpQuest.unity`（同一程序集，由菜单从代码生成并注册）：`JumpQuestRules`（纯逻辑：跳跃弧线、按住跳更高、**最小平移量**的碰撞解算、踩怪与侧撞判定、关卡生成与**可通过性校验**）+ `JumpQuestGame`（玩法 / 相机跟随 / 敌人巡逻 / 金币与终点）+ `JumpQuestHud`（IMGUI + 按住式触屏方向键，借 `MobileTouch` 同时按住"走"和"跳"）。关卡是生成的，但**生成后必须通过校验**（每个缺口都短于一次跳跃、每级台阶都低于一次跳跃、一定有终点），不通过就重新生成——"过不去的关卡"是 bug，不是难度。金币 1 币/个 + 通关 15 币。实测：走过金币会被收集、踩怪不掉命、掉坑掉命、碰到旗子结算（钱包 4053 → 4069） |
| G7 | 现有跑酷 | ✅ | 2-11 | 三车道 + 手势操作，跑酷结算自动入账宠物币 |
| G8 | 宠物之间互相交流 | ✅ | 10 | `PetChatter`：6 种交流，按两只宠物的性格挑，本地文案表**零 token** |
| G9 | 接果子小游戏 | ✅ | 13-14 | 新场景 `Assets/MiniGames/Scenes/CatchFruit.unity` + `CatchRules`（纯逻辑：篮子边界、帧率无关、难度两条曲线封顶、**篮子永远来得及横穿屏幕**、生成位置可读、金币与评价）。**第 14 轮把操作从"按住左右两个圆键"改成"左右滑动屏幕"**：`DragTo` + `PixelsToWorld` 让篮子滑多少走多少，整屏都是控制区；拖动在 `Update` 里读并 `ConsumeFrameDelta()`，避免 IMGUI 一帧两遍把距离乘二。实测：模拟 360px 拖动 → 篮子移动 3.467 单位，与公式**完全一致且只生效一次**（`docs/evidence/mobile_catchfruit_swipe.png`） |
| G10 | 记忆配对小游戏 | ✅ | 13-14 | 屋里面板（不占场景）。`PetMemoryMatch` 是纯状态机（成对洗牌、配对入账、不匹配 0.85 秒后盖回、按种子可复现）。**第 14 轮三处重做**：①卡片正面改成**程序化画的小动物头像**（`PetAvatarArt`，96×96 逐像素栅格化 + 2×2 超采样，八种动物）；②**配对成功会消失**（绿色闪一下 → 动物缩小淡出 → 那一格空掉，0.45 秒）；③**三档难度**（简单 4 对 / 中等 6 对 / 困难 8 对，奖励最多 20 / 30 / 45 币，难度会记住）。实测：困难档 16 张牌正常铺开、狐狸与青蛙头像清晰、配对两格确实变空（`docs/evidence/mobile_memory_hard.png`） |

## 这一轮（第 14 轮）的验收清单

- [x] **宠物会说话**：朗读默认打开（`dshpet.tts` 缺省为 1，单测盯着这个默认值），「▶ 测试朗读」也顺手把开关打开
- [x] **麦克风按钮**：折叠聊天栏从 68 → 80 设计像素、麦克风圆按钮 52 → 64（能看清、够大）；没权限时按下**自动重试**（拿到权限立即开始听，25 秒超时给明确指引）
- [x] **国产 ROM 的识别**：Intent 里带上 `EXTRA_CALLING_PACKAGE`（包名），失败时错误码显示在聊天里而不是静默
- [x] **「和它说说话」点得动**：摇杆抓取区 = 提示虚影所在矩形（不再是盖住聊天栏的大矩形）；整个聊天栏都是热区；`MobileWidgets` 每个按钮都有裸指针兜底；重叠时面积小的赢
- [x] **接果子改成左右滑动**：两个圆键删掉，整屏拖动、篮子跟手；拖动只在 `Update` 读一次（IMGUI 双遍不会翻倍）
- [x] **记忆配对**：卡片是小动物头像（八种，程序化绘制、单测保证八张脸互不相同）；配对成功闪一下并消失；三档难度且奖励不同、难度会记住
- [x] 225 → **235** 单测全绿（记忆配对难度/奖励 4、头像 2、盘面 1、TTS 默认开 1、接果子拖动 3）
- [x] 编辑器实测：困难档 16 张牌 + 头像可辨 + 配对格变空；模拟拖动 360px → 3.467 单位只生效一次；手机版 HUD 截图（更大的聊天栏与麦克风）
- [x] 文档：本文件 + REQUIREMENTS 阶段 14 + CHANGELOG 第 14 轮 + DEVLOG 坑 79–83 + ROADMAP + README 计数

## 明确推迟或不做

|---|---|---|
| TTS 的**质量**验收 | 🔶 | 代码、文字处理与音色换算都有测试，但"安卓读中文好不好听、延迟多少"只能在真机上听 |
