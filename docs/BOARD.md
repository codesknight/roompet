# 开发板（需求 / 待办 / 已完成）

> 这份文件是**仓库里的开发板**：每一项需求一行，写明状态、属于哪一轮、以及"凭什么说它做完了"。
> 它和 GitHub 上的 issue / milestone 是同一批内容的两个视角——issue 用来讨论与跟踪，
> 这里用来一眼看清整个项目的全貌（以及**哪些只是写了计划、哪些真的验证过**）。
>
> 状态图例：✅ 已完成且验证 ｜ 🔶 已完成但验证有限 ｜ 🚧 进行中 ｜ 📋 待办 ｜ ⏸ 明确推迟 ｜ ❌ 不做
>
> 需求逐条的详细实现与证据见 [REQUIREMENTS.md](REQUIREMENTS.md)；
> 踩过的坑与交接信息见 [DEVLOG.md](DEVLOG.md)。

## 一、交互与界面

| 编号 | 需求 | 状态 | 轮次 | 实现与证据 |
|---|---|---|---|---|
| I1 | 点击宠物能做不同的动作 | ✅ | 9 | `PetInteraction`：点/戳宠物 → 按**性格与状态**挑一个反应（躲开、蹭手、翻肚皮、甩尾巴、装睡、炸毛…）。手机上是**点击**（触摸射线命中宠物），桌面是鼠标点击 |
| I2 | 点击宠物发出声音、说话 | ✅ | 9 | 反应会同时：①播放该物种+性格的**程序化叫声**；②以第一人称写一行反应进对话（不花 token，本地文案） |
| I3 | 不同宠物不同性格不同音色 | ✅ | 9 | `PetVoice`：基频/滑音/颤音/音节数由**物种**（狐/猫/兔/熊）+ **性格四维**共同决定，纯波形合成，可单测 |
| I4 | 语音输入（STT） | 🔶 | 12-15 | `DshMobile.MobileStt`（安卓 `SpeechRecognizer`）：麦克风按钮在折叠聊天栏里，按一下**展开聊天并开始听**，识别到的字填进输入框（不直接发送）。平台坑都按文档处理了：Android 11 的 `queries`、麦克风**运行时权限**、`RecognitionListener` 十个回调、**国产 ROM 的 `EXTRA_CALLING_PACKAGE`**，第 15 轮又加了**失败自动换问法重试一次**（带/不带 `EXTRA_LANGUAGE`）+ **重建识别器** + 错误码人话解释。**第 15 轮的真正修复是"可见"**：失败写进对话系统提示、底栏一行实时状态、按钮三态、设置里的语音诊断。**识别准确率仍只能真机验证** |
| I5 | 语音输出（TTS） | 🔶 | 10-15 | 第 10 轮 `DshMobile.MobileTts`；第 11 轮修 `queries` 与初始化失败被永久记住；第 12 轮修 `setPitch/(F)V`（那两个方法返回 int）；第 14 轮改成**默认打开**（"宠物还是不会说话"）；第 15 轮把开关**放到聊天栏上**（「朗读：开/关」+「音效：开/关」，桌面那两个 🔊/🔇 是看不见的按钮，一并换成汉字）。**发音质量仍只能在真机上听** |
| I6 | 语音系统可开可关 | ✅ | 9-15 | 三个独立开关：`PetVoice.Enabled`（叫声，默认开）、`MobileTts.Enabled`（朗读，默认开）、`MobileStt.Enabled`（麦克风按钮，默认开）。第 15 轮起**朗读与音效都能在聊天栏上直接切换**并在对话里留下一条系统提示 |
| I7 | 每只宠物一张状态卡 | ✅ | 11 | `PetGameManager.Cards()` 给房间里每只宠物一份卡片数据（名字/物种/性格/需求/控制器），`PetHud.DrawPetCards` 用**宠物名字做页签**渲染；点房间里的宠物 = 选中它的卡片（`PetClickTarget` → `SelectPetObject`）。同伴的需求以前**根本不衰减**（只有主宠被 tick），现在一起 tick，并按所在地应用同样的修正 |
| I8 | 状态卡可隐藏 / 可打开 | ✅ | 11 | 卡片可折叠：折叠后只剩页签 + 一行摘要 + `展开/地图/设置`；展开时是完整卡片。点已选中的页签切换折叠。折不下时会自动退回短卡（`ComputeCardLayout` 的三条规则，单测逐个视口验证） |
| I9 | 删掉与背包重复的「换一只」卡片 | ✅ | 11 | 那张卡被整段删除（连同 `DrawSpeciesSwitcher`），并在原处留了注释说明为什么：它和「宠物」面板的背包页重复，而且那个按钮会**静默换掉你正在照顾的那只**（连记忆一起）。房间里有谁由背包决定，卡片只负责"读" |
| I10 | 保留「视角」卡片 | ✅ | 11 | `ViewCardHeight` 固定高度，位置由 `HudLayout.Switcher` 决定；新卡片与它、与聊天面板**互不重叠**（单测用真实矩形做 `Rect.Overlaps` 检查） |

## 这一轮（第 17 轮）的验收清单

- [x] **小游戏回来后人不能动**：找到真因——小鸟游戏的**整屏**点击区在触控层里活过了场景切换，而输入分发先查按钮后查摇杆，于是摇杆区的手指令被判给那个不存在的按钮；现在场景加载时清空触控层
- [x] **森林奔跑暂停后回房间也是停的**：`Time.timeScale` 全局且跨场景存活；新增 `SceneClock.Restore()`，场景加载 + 各游戏返回 + 枢纽兜底，且不干扰慢动作
- [x] **语音识别的主线程异常**：所有识别器调用经 `runOnUiThread` 兜住（已主线程就地执行，否则投递），每个 Runnable 自己抓异常；诊断新增调用线程与投递次数
- [x] 248 → **250** 单测全绿（场景加载清空旧按钮 1、时钟恢复 1）
- [x] 实测：`Main → FlyBird → PetRoom` 后探针从 `fly.tap` 变 `null`；暂停的森林奔跑返回后 `timeScale=1`、按钮清空、摇杆可用
- [x] 文档：本文件 + REQUIREMENTS 阶段 17 + CHANGELOG 第 17 轮 + DEVLOG 坑 100–102 + README 计数
